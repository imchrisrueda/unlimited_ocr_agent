## Notes

### Contexto y motivación arquitectónica

En la visión de `mejoras.md`, la imagen original del documento es la **fuente primaria de evidencia y verdad**, mientras que el texto extraído por Unlimited-OCR actúa como hipótesis o contexto complementario para asistir al modelo de visión y lenguaje (VLM).

En el hardware de 12 GB de VRAM (NVIDIA RTX 4070 Ti 12 GB), `Unlimited-OCR` y `Qwen 3.5 9B` se ejecutan en fases estrictamente secuenciales:
1. **Fase 1 (OCR)**: Rasterizado de páginas a imágenes e inferencia OCR mediante subproceso worker aislado (PR 3).
2. **Fase 2 (Liberación)**: Terminación del subproceso worker y liberación determinista de la memoria CUDA por parte del SO.
3. **Fase 3 (VLM Multimodal)**: Consulta multimodal a LM Studio local (`Qwen 3.5 9B`), enviando la imagen rasterizada junto con el texto OCR correspondiente y una instrucción estructurada.

El cliente actual `LMStudioClient` en `src/fieldnotes/vlm/lmstudio.py` presenta varias limitaciones que se corrigen en este PR 4:
- Solo admite texto (`ask` y `ask_chunked`), sin capacidad para enviar imágenes.
- Resuelve modelos seleccionando ciegamente el primer candidato en `/v1/models` (`candidates[0]`), lo que puede dirigir peticiones a modelos no previstos o no multimodales.
- Ante errores de red o API, captura la excepción y retorna un string (`"Error al conectar con LM Studio: ..."`), impidiendo que el llamador gestione el error mediante excepciones tipadas.
- Si el modelo agota los tokens en razonamiento y devuelve contenido vacío, imprime un mensaje pero no levanta una excepción recuperable.
- No ofrece soporte para `response_format` (JSON object / Schema), necesario como base para los esquemas estructurados de PR 5.

### Diseño técnico y reglas de contrato para PR 4

#### 1. Resolución determinista de modelos y precedencia estricta
Queda prohibido utilizar heurísticas de búsqueda por subcadena (p. ej. `'qwen' in id`) o seleccionar automáticamente el primer modelo disponible (`candidates[0]`).
El orden de resolución es estrictamente determinista:
1. Argumento explícito `model` en la llamada a `ask_text()` o `ask_vision()`.
2. Modelo configurado en el constructor del cliente: `vision_model` (para visión) o `text_model` (para texto).
3. Variable de entorno específica: `LM_STUDIO_VISION_MODEL` (para visión) o `LM_STUDIO_TEXT_MODEL` (para texto).
4. Fallback legacy: argumento `default_model` en constructor o variable `LM_STUDIO_MODEL` (aplicado como modelo de texto por defecto; solo sirve como fallback de visión si se invoca explícitamente una ruta de código legacy y nunca sobreescribe a `LM_STUDIO_VISION_MODEL`).

Si tras evaluar la precedencia no existe un modelo configurado:
- Se lanza `LMStudioModelNotConfiguredError`.
- El mensaje de error incluye la lista de identificadores de modelos anunciados por `/v1/models` a modo de diagnóstico para asistir al usuario en la configuración.
- Los modelos configurados se validan contra `/v1/models` una sola vez y se cachean por instancia de cliente, con opción de desactivar la comprobación (`validate_model=False`) para entornos con modelos dinámicos.

#### 2. Jerarquía de excepciones tipadas y seguridad
Se define una jerarquía en `src/fieldnotes/vlm/lmstudio.py`:
- `LMStudioError(Exception)`: Excepción base del subsistema VLM.
- `LMStudioConnectionError(LMStudioError)`: Fallos de conexión de red, servidor inalcanzable o timeout del SDK.
- `LMStudioModelNotConfiguredError(LMStudioError)`: No se ha configurado ningún modelo para la operación solicitada.
- `LMStudioModelNotFoundError(LMStudioError)`: El modelo configurado no está cargado o anunciado en el servidor.
- `LMStudioResponseError(LMStudioError)`: Códigos de estado HTTP 4xx/5xx devueltos por la API o respuestas malformadas.
- `LMStudioEmptyResponseError(LMStudioError)`: La respuesta del modelo no contiene texto generado (p. ej. tokens consumidos enteramente en razonamiento).

**Reglas de seguridad y encadenamiento:**
- Toda excepción capturada del SDK debe propagarse preservando la causa raíz: `raise LMStudioConnectionError(...) from exc`.
- Los mensajes de error y logs **nunca deben volcar claves API ni cadenas base64 completas** de imágenes (se redactan o se indica solo la ruta y tamaño).

#### 3. Validación y codificación segura de imágenes
Función `encode_image_to_data_uri(image_path: str | Path, max_bytes: int = 20 * 1024 * 1024) -> str`:
- Verifica que `image_path` exista y sea un archivo regular (`is_file()`).
- Valida la extensión (`.png`, `.jpg`, `.jpeg`, `.webp`, `.bmp`).
- Comprueba las firmas de bytes mágicos iniciales mediante funciones auxiliares de stdlib para asegurar integridad antes de leer el archivo completo.
- Comprueba que el tamaño en bytes no supere `max_bytes` (por defecto 20 MiB) para evitar desbordamientos de memoria.
- Genera la cadena Data URI estándar `data:<mime>;base64,<encoded>`.
- No realiza logging del contenido base64 generado.

#### 4. Interfaz de `LMStudioClient` y structured outputs
- **`ask_text(...)`**:
  - Parámetros: `prompt`, `context=None`, `system_prompt=None`, `model=None`, `reasoning_effort="none"`, `max_tokens=2048`, `temperature=0.2`, `response_format=None`.
  - Construye mensajes del sistema y usuario, omitiendo kwargs opcionales cuando sean `None`.
  - Si se proporciona `response_format`, se pasa directamente a `client.chat.completions.create` sin mutación (p. ej. `response_format={"type": "json_object"}`).
- **`ask_vision(...)`**:
  - Parámetros: `image_path`, `prompt`, `ocr_context=None`, `system_prompt=None`, `model=None`, `reasoning_effort="none"`, `max_tokens=2048`, `temperature=0.2`, `response_format=None`.
  - Construye el payload multipart compatible con OpenAI:
    ```python
    user_content = [
        {"type": "text", "text": formatted_prompt_with_ocr},
        {"type": "image_url", "image_url": {"url": data_uri}},
    ]
    ```
- **Retrocompatibilidad**:
  - `ask(document_text, question, ...)`: preservado, delega en `ask_text(prompt=question, context=document_text, ...)`.
  - `ask_chunked(...)`: preservado, delega en `ask()`.
  - Propiedad `lm_model`: mapea a `text_model` por defecto.

#### 5. Integración en `UnlimitedOCRAgent` y CLI
- **Pipeline (`src/fieldnotes/pipeline.py`)**:
  - Constructor acepta `vision_model: Optional[str] = None`, `text_model: Optional[str] = None`, `lm_model: Optional[str] = None`.
  - Métodos `agent.ask_vision(image_path, prompt, ocr_context=None, ...)` y `agent.ask_page_vision(page_artifact, prompt, ...)`.
  - Garantía de secuencialidad: las consultas a `vlm` se ejecutan exclusivamente tras el retorno y terminación completa del proceso worker de Unlimited-OCR (PR 3).
- **CLI (`src/fieldnotes/cli.py`)**:
  - Flags: `--vision-model`, `--text-model`, `--lm-model` (legacy).
  - Flag `--ask-vision`:
    - En imágenes individuales: procesa OCR worker y ejecuta `ask_vision` sobre la imagen con su texto OCR.
    - En PDFs: procesa el OCR worker sobre todas las páginas, y posteriormente ejecuta `ask_vision` de forma estrictamente secuencial sobre cada `PageArtifact` (una petición VLM por página), devolviendo una concatenación delimitada simple (p. ej. `### Página 1\n...\n\n### Página 2\n...`) sin realizar estructuración ni fusión de páginas (reservado para PR 5 y PR 6).
    - Valida que exista un modelo de visión configurado y falla claramente con `parser.error` si falta configuración.

#### 6. Estrategia y suite de pruebas
- **Tests unitarios offline (`tests/test_vlm.py`)**:
  - Precedencia estricta de resolución de modelos (por llamada > constructor > variable de entorno > legacy).
  - Fallo determinista con `LMStudioModelNotConfiguredError` y diagnóstico de modelos cuando no hay configuración.
  - Caché de validación de modelos por instancia.
  - Validación de imágenes: extensiones, firmas de bytes mágicos, archivos inexistentes, exceso de límite de tamaño (20 MB) y redacción de base64.
  - Payload multipart de visión con Data URI e inclusión de contexto OCR.
  - Comportamiento de `response_format` (pasado solo cuando no es `None`, sin mutación).
  - Omisión de kwargs opcionales `None`.
  - Excepciones tipadas encadenadas (`raise ... from exc`) con redacción de claves API y base64.
  - Retrocompatibilidad de `ask()` y `ask_chunked()`.
- **Prueba de integración real opt-in (`TestRealLMStudioVisionIntegration`)**:
  - Gated por `RUN_LMSTUDIO_VISION_INTEGRATION=1`.
  - Si el flag **no** está activo: se omite limpiamente con `skipTest` explicando cómo activarlo.
  - Si el flag **sí** está activo: la ausencia de servidor, modelo o archivo de prueba genera un **fallo real** (`AssertionError`/`Error`), no un skip silencioso.
  - Registra el ID de modelo utilizado y verifica que la respuesta sea no vacía sin volcar payloads de imágenes a la salida.
- **Tests de pipeline y CLI (`tests/test_pipeline.py`, `tests/test_cli.py`)**:
  - Verificación de `ask_vision` y `ask_page_vision`.
  - Verificación de procesamiento secuencial por página en `--ask-vision` para PDFs.
