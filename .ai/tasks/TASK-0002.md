## Notes

### Contexto técnico y diseño del particionado por página
En `unlimited_ocr_agent`, la inferencia sobre documentos multipágina (`infer_multi`) ejecuta una sola llamada al modelo de visión pasando la lista de imágenes rasterizadas. El resultado generado en `result.md` concatena el texto reconocido separando las distintas páginas mediante marcas `<PAGE>`.

Para avanzar hacia la arquitectura descrita en `mejoras.md` cumpliendo con las directrices de Codex para el PR 2:
1. **Estructura del Run**: Dentro del directorio temporal del run (`output_dir`), se organizan los artefactos en dos carpetas principales:
   - `pages/`: contiene las imágenes de cada página con formato de 3 dígitos (`page_001.png`, `page_002.png`, etc.).
   - `raw/`: contiene el documento OCR agregado íntegro (`raw/document.md`, byte y textualmente idéntico a `result.md`) y, cuando el mapeo sea exitoso, los archivos individuales por página (`raw/page_001.md`, `raw/page_002.md`, etc.).
2. **PageArtifact con estado auditable explícito**: Se implementa como `@dataclass` usando únicamente tipos de la biblioteca estándar (`dataclasses`, `pathlib`, `typing`):
   ```python
   from dataclasses import dataclass
   from pathlib import Path
   from typing import Optional, Literal

   MappingStatus = Literal["pending", "mapped", "unaligned"]

   @dataclass
   class PageArtifact:
       page_number: int  # 1-based
       image_path: Path
       raw_ocr: Optional[str] = None
       ocr_mapping_status: MappingStatus = "pending"
       mapping_error: Optional[str] = None
   ```
3. **Mapeo determinista, literal y seguro**:
   - **Preservación textual literal**: No se normalizan espacios ni saltos de línea en el texto raw. `raw/document.md` refleja de manera fidedigna el contenido de `result.md`.
   - **Regla de delimitador**: La división en bloques retira exclusivamente la etiqueta estructural `<PAGE>` de acuerdo con una regla documentada (ej. coincidencia exacta de token o patrón de delimitador).
   - **Comprobación de prefacio**: Si existe contenido no vacío antes del primer `<PAGE>`, todo el documento se considera `unaligned`, se asigna `mapping_error="Se detectó texto no vacío previo al primer delimitador <PAGE>"`, `raw_ocr` permanece en `None` y no se emiten archivos `raw/page_*.md`.
   - **Comprobación de correspondencia 1:1**:
     - Si `len(blocks) == len(page_images)` y no hubo prefacio, cada bloque `blocks[i]` se asigna literalmente a la página `i+1`, persistiendo `raw/page_{i+1:03d}.md`, marcando `ocr_mapping_status="mapped"` y `mapping_error=None`.
     - Si `len(blocks) != len(page_images)`, se asigna `ocr_mapping_status="unaligned"` con `mapping_error=f"Discrepancia en el conteo de páginas: se esperaban {len(page_images)} pero se encontraron {len(blocks)} bloques <PAGE>"`, conservando únicamente `raw/document.md`.
4. **Compatibilidad de APIs y wrappers**:
   - `extract_pdf_images(pdf_path, output_dir)` se mantiene como wrapper compatible que retorna `list[str]`.
   - Se introduce una función nueva (ej. `extract_pdf_page_artifacts(pdf_path, output_dir) -> list[PageArtifact]`) para generar `PageArtifact`s con imágenes en `pages/page_{i:03d}.png`.
   - `UnlimitedOCRAgent.extract_from_pdf` continuará retornando el string agregado completo.
   - La CLI y todas sus opciones permanecen inalteradas.
5. **Aislamiento y control en tests**:
   - Todas las pruebas unitarias deben ejecutarse en carpetas temporales (`tempfile.mkdtemp()`) y limpiarlas rigurosamente en `tearDown()`.
   - La suite por defecto (`python -m unittest`) nunca debe cargar modelos ni requerir GPU/red.
   - Las pruebas de integración con OCR real y el archivo local `26-05-06.pdf` deben estar desactivadas por defecto mediante `@unittest.skipUnless(os.getenv("RUN_OCR_INTEGRATION") == "1", "Prueba de integración desactivada por defecto; requiere RUN_OCR_INTEGRATION=1")`.
